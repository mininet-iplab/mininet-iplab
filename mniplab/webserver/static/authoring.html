      Host

        * Required

        Spanning tree

        Lower priorities win the root election. RSTP uses multiples of 4096, up to 61440.

        Nameservers

        Choose Nodes by identity so renaming one keeps this Host pointed at it. The Node needs a static Interface address. You can also enter IP addresses.

        Position

        Protocols

        Each Protocol starts its FRR Daemon. zebra and staticd always run, so static routes need none.

        On by default: every Interface of this Router gets hello 1 s and dead 3 s when the Lab starts, so neighbours form and routes appear within seconds. These lines are not shown in the FRR configuration below, and timers you write there take precedence. Turn this off to use FRR's defaults (hello 10 s, dead 40 s); the Lab can then take 40 s or more to converge.

        Native FRR commands, as in frr.conf. The hostname line is added for you.

        VLAN subinterfaces

        Choose an attached parent Interface and VLAN ID. Addresses follow the Lab's address family.

        VRFs

        Each VRF is a separate routing table on this Router. Place an Interface in one on the Interfaces tab; configure its routing in the FRR configuration.

        Router NAT

        Port forwards and static 1:1 mappings this Router translates when the Lab starts. Mark an Interface outside on the Interfaces tab first; each entry applies to an outside Interface.

        BGP Speaker

        The Speaker listens passively. Configure the peering Router in its FRR configuration to open each Neighbor session and allow the route policy you intend.

        Route generators
        Neighbors *

        Each Neighbor has a peer, a local address of its own, both AS numbers and an optional hold time. Pick the peer from another Node's Interfaces, or type any address. A Neighbor with Routes announces only those; one without inherits the Global Routes. Generators use the Neighbor's family and local address as next hop. Hand-written Routes are under More and announce alongside generated ones.

        Global Routes

        The same seeds and count apply to each Neighbor without its own generator. Each uses its own local address and family. Sub-prefix counts are an upper bound: shorter ranges may fit fewer. Hand-written Global Routes apply to Neighbors without hand-written Routes of their own.

        More · Hand-written Global Routes

        Internet Gateway

        Internet Gateways use IPv4. Choose IPv4 or Dual-stack in the Lesson tab to configure one.

        Downstream Routers

        Choose the Routers whose traffic this Transit Internet Gateway translates.

        Services

        Tick a Service to configure it on this Node.

        Kea serves one Pool per Subnet this Node is attached to. A Subnet without a Pool gets no answer; another Node may also serve the same Subnet.

        Pools

        Each Pool serves one Subnet, and the Subnet sets its family: Preferred lifetime is IPv6 only and Router is IPv4 only, because an IPv6 client takes its default route from the Router Advertisement. An IPv4 Reservation names a MAC address; an IPv6 Reservation names exactly one of a MAC address or a DUID. Leave Lease time empty for Kea's default. Pin the client's MAC address in its Link.

        A Primary holds authored Records. A Secondary receives its Records by Zone Transfer and has no seeded Records.

        Zones

        A Primary holds authored Records. Use @ for the apex or enter a relative owner such as web. Record types are A, AAAA, CNAME, PTR, TXT, MX, NS and SOA. New Records start with the Zone's default TTL; change an individual TTL under More. Omit SOA or apex NS to use the DNS Service's defaults. DNSSEC generates signing keys and signatures when the Lab starts; KASP stores the signing keys. NSEC3 requires DNSSEC and uses hashed denial of existence; its optional salt is pairs of hexadecimal digits. A DS delegation names a signed child Primary Zone on another Node; the parent must also be signed. Transfer permission: Default permits declared Secondaries, None refuses transfers, and Listed permits only the chosen Nodes or addresses.

        * Required. Apex ends in a dot; @ names the apex Record owner.

        Choose another Node's Primary Zone. Its stable Node ID is saved so a rename keeps the Zone Transfer relationship.

        Choose an in-lab Root for iterative resolution, or enter upstream forwarders. Forwarders take precedence when both are set.

        Root Hints

        Choose Nodes by identity; their Interface addresses are read when the Lab starts.

        DNSSEC trust anchors

        Choose a Node serving a signed root Zone. Its trust anchor is generated when the Lab starts.

        Access Control rules

        Each rule has a Subnet and an action: allow, refuse or deny. Unbound applies the most specific matching Subnet.

        Forwards DHCP requests from attached Subnets to a DHCP Service elsewhere. A server that cannot be reached is allowed: requests time out, which a lesson may intend.

        Subnet CIDRs, separated by commas.

        DHCP servers *

        The DHCP Service's address: one IPv4, one IPv6, or one of each. Pick an Interface of another Node, or type any address; a server that cannot be reached is allowed.

        Krill runs on this Node and holds one Hosted CA per Autonomous System, each signing only for the prefixes it holds. A Lab has at most one RPKI CA.

        The DNS name Krill is reached by, and names in its certificate. Leave it empty to use this Node's name, which must then be a DNS name.

        Hosted CAs *

        Each Hosted CA is one Autonomous System's certificate authority. Its prefixes are the only resources it can sign for. Starting ROAs take one line each as prefix[-maxLength] => origin, such as 10.1.0.0/24-24 => 65002. Starting ASPAs take one line each as ASn => ASm, ASk, where ASn is this Hosted CA's ASN. Both must fall within its resources.

        Routinator on this Node fetches the Lab's RPKI objects from its RPKI CA and serves them to Routers over RTR. A Lab with a Validator needs an RPKI CA.

        Seconds between validation runs. The default, 10, lets a Learner see a change within about a quarter of a minute.

        Startup commands

        Before daemons runs once Interfaces are up, before FRR and Services start. After start runs when the Lab has started. Nodes run in parallel; this Node's commands run in order. A failing or timed-out command stops the Lab start unless it may fail.
